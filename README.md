# presentation

Generated by **Automatic / Local Dev Studio**.

The generated project is intentionally split into three independent areas:

```text
presentation/
├── front/   # browser/UI framework
├── back/    # public API / business logic
├── ml/      # internal ML/AI service
├── docker-compose.yml
├── .gitignore
└── README.md
```

Only selected folders are created. The architectural rule when all three are present is:

```text
Browser -> front -> back -> ml
                   ^      |
                   +------+
```

The frontend should normally call the backend. ML is intended to stay behind the backend rather than becoming a public browser API.

## Selected stack

- **front**: Next.js — React meta-framework for production web apps with App Router, server rendering, route handlers, streaming, metadata, and strong Vercel integration.

## Run each component locally

### front: Next.js
```bash
cd front
npm run dev -- -H 0.0.0.0 -p 3000
```

## Docker development

All selected components have a Docker development profile.

```bash
docker compose up
```

- Front: http://localhost:3000
- Back: http://localhost:8000
- ML: internal Docker service `ml:8001` (not published by default)

## How this generator is extended

The generator itself uses plugin folders:

```text
automatic_builder/
├── front/
│   ├── main.py
│   └── frames/
│       └── <framework>.py
├── back/
│   ├── main.py
│   └── frames/
│       └── <framework>.py
└── ml/
    ├── main.py
    └── frames/
        └── <framework>.py
```

To add a framework, add one Python module containing a `FrameworkSpec`. The registry auto-discovers it; you do not need to edit a central switch statement.
